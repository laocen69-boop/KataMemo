# 词库贡献与新增词汇工作流

本文档面向希望为 **KataMemo** 补充新词、修正释义/例句或替换发音音频的贡献者，约定统一的数据结构、语言校对标准与本地校验流程。

---

## 1. 数据文件与字段说明

词库主数据位于 `app/assets/data/words.json`（JSON 数组），配套音频分片打包在 `app/assets/audio_pack/`（`ardi_00.pak` ~ `ardi_15.pak` + `ardi_idx.tsv`）。

### 核心字段表

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `id` | 是 | `string` | 唯一键，**必须全小写且不含重音符（é/ê 等）**；一经发布**不可修改**（学习进度、收藏与音频索引均绑定此键） |
| `w` | 是 | `string` | 界面展示词形（可保留专有名词大小写或教学标音 `é`/`ê`） |
| `t` | 是 | `string` | 所属分层：`t1`–`t7`（按词频学习层）、`advanced`、`phrase`（词组）、`derived`（派生词）、`redup`（重叠词）、`proper`（专名）、`affix`（词缀）、`lookup`（只查不学，配合 `en: 0`） |
| `zh` | 是 | `string` | 中文释义；**多个义项之间用中文全角分号 `；` 分隔** |
| `c` | 建议 | `string` | 主词性：`n`、`v`、`a`、`adv`、`num`、`part`、`pron`、`interj`、`conj`、`prep`（词组可省略） |
| `pa` | 可选 | `string` | 多词性列表（逗号分隔，如 `"n,pron"`） |
| `r` | 可选 | `int` | 语料词频排名 |
| `ph` | 可选 | `string` | 音标（需要区分 `/ə/` 与 `/e/` 时建议补充） |
| `ex` | 建议 | `list` | 例句数组，每项为 `{"i": "印尼语例句", "z": "中文译文", "q": "挖空目标词"}` |
| `au` | 建议 | `dict` | 音频引用，例如 `{"a": "edge/ardi/id-rumah.ogg"}` |
| `tp` | 可选 | `list` | 主题标签数组（如 `["人称代词"]`、`["日常饮食"]`） |
| `pk` | 专名 | `string` | 专名细类（如 `people`、`place`、`org`、`work`、`deity`） |
| `en` | 可选 | `int` | 是否默认启用学习（`1` 或省略 = 启用；`0` = 仅查词） |

## 2. 新增一个词的标准五步工作流

### 第 1 步：查重与准入判断（宁缺毋滥）
1. **折叠查重**：先忽略大小写与 `é`/`ê` 音符检查 `id` 是否已存在（含 `lookup` 和 `derived`）。已存在则走**修改**而非新增。
2. **权威核验**：优先核对官方权威词典（KBBI）与规范印尼语参考资料/主流语料：
   - 确认是真实印尼语词或高频规范借词；
   - 警惕英文同形词在网络语料中虚高（例如仅在英文网页出现的词不收入印尼语学习层）。
3. **定层**：常规词汇按实际使用频率归入对应学习层（不确定时可暂放 `t5`–`t6` 或 `lookup`）；固定搭配归 `phrase`；人名/地名/机构归 `proper` 并填 `pk`。

### 第 2 步：编写词形、释义与例句
1. **拼写与正字法（EYD）**：
   - 严格区分介词 `di` / `ke`（**分写**，如 `di rumah`、`ke pasar`）与词缀 `di-` / `ke-...-an`（**连写**）；
   - 重音符号仅在确实需要区分元音 `/e/` 与央元音 `/ə/` 的教学展示形 `w` 中使用，`id` 保持纯 ASCII 小写。
2. **中文释义对齐**：
   - 简明准确，避免生硬机器直译；多义项按常用度排序，使用全角分号 `；` 分隔。
3. **例句规范**：
   - 学习层词条建议至少配 **1～3 条自然地道、符合现代印尼语语法的例句**，去除口语冗余词；
   - 确保 `q` 字段与例句中出现的目标词形匹配，保证拼写/挖空题可正常出题。

### 第 3 步：生成与试听音频
仓库提供零密钥的本地音频生成与打包脚本（需安装 Python `edge-tts` 与 `imageio-ffmpeg`）：

```bash
# 1. 生成标准 24kHz 单声道 16kbps Opus .ogg
python tools/synth_audio.py "rumah" id-rumah.ogg --rate=-10%
```

> **重要提示（必须人工试听）**：对于单音节词或含 `e` 的高频虚词（例如 `ke` 应读 `/kə/` 而非 `/kɛ/`），TTS 直接单读容易误读。可尝试用引号包裹文本（如 `'"ke"'`）或微调 `--rate`（如 `-25%`），**务必亲自试听确认发音准确、收尾自然不短促后再入库**。

### 第 4 步：写入音频包与词库
```bash
# 将生成或替换的 .ogg 写入 app/assets/audio_pack/ 并自动更新 ardi_idx.tsv
python tools/pack_audio.py replace id-rumah.ogg

# 如需从现有分片中提取某条音频对比试听：
python tools/pack_audio.py unpack id-ke.ogg --out ./tmp
```

然后在 `app/assets/data/words.json` 中新增或修改对应词条；**若词库内容有实质变动，请同步递增 `app/lib/db.dart` 中的 `kDataVersion`**，确保老版本用户升级后能触发本地数据库重导。

### 第 5 步：本地全量自检（PR 门禁）
提交 Pull Request 前，请依次运行以下两条检查（与 GitHub Actions CI 一致）：

```bash
# 1. 校验全库 JSON 结构、必填字段、音频包边界与 9 万+ 音频引用零断链
python tools/validate_data.py
python tools/pack_audio.py verify

# 2. 运行 Flutter 静态检查与全量测试
cd app
flutter pub get
flutter analyze --no-pub
flutter test --no-pub
```

---

## 3. 贡献红线
- **不要删除已有音频条目**：`ardi_idx.tsv` 中的历史音频均经过校验与保留，只允许修正或新增。
- **不要改动已有词条的 `id`**：改 `id` 会导致用户原有 FSRS 记忆记录和音频引用脱钩。
- **不要提交未核实的机器直译或口语错拼**：拿不准的词条建议先在 Issue 中讨论确认。
